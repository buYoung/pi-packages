# 변경 이력

0.1.2까지의 변경 이력은 영문 [CHANGELOG.md](CHANGELOG.md)에만 있습니다.

## [Unreleased]

### 해결된 것

- Manual authorization code 로그인이 Devin CLI와 같은 로그인 페이지를 열고, 같은 방식으로 코드를 교환합니다. 이전에는 로그인 URL이 404 페이지를 보여 줘서 로그인을 끝낼 수 없었습니다.
- Claude 모델이 한 응답에서 도구를 여러 개 부를 수 있습니다. 이전에는 이런 응답이 "Cannot attach a delta without a tool ID to a specific call."로 실패했습니다.
- 결과가 없는 도구 호출이 기록에 남은 세션도 다시 동작합니다. 예를 들어 `/tree`로 다른 지점으로 옮긴 뒤 이런 기록이 생깁니다. Pi의 기본 공급자처럼 그 호출에 "No result provided" 오류 결과를 붙입니다. 이전에는 그 세션의 모든 Devin 요청이 `invalid_argument`로 실패했습니다.
- Pi의 기본 공급자처럼 출력 한도를 모델의 컨텍스트 창에서 입력을 뺀 만큼으로 줄입니다. 이제 컨텍스트가 가득 차면 응답이 `length`로 끝나고, Pi가 compact로 복구합니다. 이전에는 창보다 큰 입력을 계속 보낼 수 있었습니다.
- 긴 세션에서도 Claude의 프롬프트 캐시가 계속 늘어납니다. Pi의 Anthropic 공급자처럼 가장 최근 user 메시지나 도구 결과 하나에만 캐시 표시를 붙입니다. 이전에는 모두에 붙여서 처음 몇 번의 요청 뒤로 캐시가 늘지 않았고, 나머지 대화는 매번 캐시 없이 보냈습니다.
- 프로세스 안에서 도는 서브에이전트처럼 Pi 모델 런타임 하나를 함께 쓰는 세션들이 각자의 Devin 실행을 유지합니다. 이전에는 마지막에 시작한 세션이 모든 세션의 Devin 요청을 받았고, 그 세션이 끝나면 다른 세션의 요청이 "The Devin provider shut down."으로 실패했습니다. 그 세션의 첫 요청도 "No Devin model list matches the current account and endpoint."로 실패할 수 있었습니다.

### 해결된 것

- 0.1.7이나 0.1.8에서 업데이트한 뒤 Pi가 `Cannot find module '…/effect/dist/process/CommandLine.js'` 오류로 시작하지 못하던 문제를 고쳤습니다. 이 버전들이 Pi 패키지 폴더에 더 새 `@effect/platform-node-shared`를 남겼고, 0.1.10도 이를 그대로 썼습니다. 이제 `@effect/platform-node`와 `@effect/platform-node-shared`를 패키지 안에 함께 담아 배포하므로, 다른 패키지나 이전 버전이 무엇을 설치했든 항상 이 패키지의 `effect`를 씁니다.

## [0.1.10] - 2026-11-02

### 해결된 것

- 이 패키지를 설치하거나 업데이트한 뒤 Pi가 다시 정상적으로 시작합니다. 다른 패키지가 `effect` 4.0.7을 설치해 둔 환경에서는 0.1.9도 `Cannot find module '…/effect/dist/process/CommandLine.js'` 오류로 실패했습니다. Pi가 peer 의존성을 풀지 않고 패키지를 설치하기 때문입니다. 이제 `effect`와 Node 플랫폼 패키지를 다른 패키지와 같은 4.0.7로 두고, `@effect/platform-node-shared`도 이 버전으로 고정합니다.

## [0.1.6] - 2026-10-25

### 달라진 것

- Pi에서 사용자 메시지 하나가 보낼 수 있는 모델 요청 수를 더 이상 제한하지 않습니다. 이전에는 도구 후속 요청, 재시도, 자동 압축을 포함해 기본 8번 요청한 뒤 `Used all 8 Devin model HTTP requests in the budget.` 오류로 멈췄습니다. `PI_DEVIN_MAX_MODEL_CALLS`를 없앴으며 설정해도 무시합니다. `/devin`도 더 이상 실행 예산을 보여 주지 않습니다. 이전 버전에서 저장한 세션도 그대로 쓸 수 있습니다. 함께 배포하는 CLI의 `--max-model-calls` 옵션은 바뀌지 않습니다.

### 해결된 것

- Pi의 `retry.provider.maxRetries`가 0이 아니거나, 다른 공급자를 위해 `transport`를 WebSocket으로 설정했을 때 Devin 요청이 실패하던 문제를 고쳤습니다. 지원하지 않는 공급자는 무시하라는 Pi의 기대대로 두 설정을 무시합니다.
- 계속 들어오는 긴 응답이 Pi의 요청 제한 시간(기본 300초)이 지나면 끊기던 문제를 고쳤습니다. 이제 그 시간 동안 데이터가 전혀 오지 않을 때만 실패합니다.
- 오류 본문이 함께 온 사용량 제한·서버 오류(예: HTTP 429의 `resource_exhausted`, `internal`)를 이제 Pi의 자동 재시도가 다시 보냅니다. 할당량·과금 오류는 여전히 재시도하지 않습니다.
- 도구를 호출하다가 출력 한도에 닿았거나, 올바른 JSON이 아닌 인자로 도구를 호출하면, 차례를 오류로 끝내지 않고 모델에게 알려 다시 호출하게 합니다. 이런 호출은 여전히 실행하지 않습니다.
- 이미지를 지원하지 않는 모델로 바꿨을 때 대화 앞쪽의 이미지 때문에 요청이 실패하던 문제를 고쳤습니다. 이전 이미지는 안내 문구로 바뀝니다.
- 실패한 응답이 앞선 도구 호출의 ID를 다시 쓰면, 앞선 정상 도구 결과까지 Devin에 보내는 이력에서 빠지던 문제를 고쳤습니다.
- 확장의 내부 구현을 Effect 4로 옮겼습니다. 요청, 로그인, 모델 목록 갱신, `/devin`, `/devin-fusion`, Fusion 사이드킥은 이전과 같이 동작합니다. 이제 패키지를 설치하면 런타임 의존성 `effect`와 `@effect/platform-node`도 함께 설치됩니다.
- 상태 표시줄의 사용량이 Devin Fusion을 포함한 Devin 모델을 선택했을 때만 보이고, 다른 공급자의 모델로 바꾸면 바로 사라집니다. `/devin`은 어떤 모델을 선택했든 계속 사용량을 보여 줍니다.

## [0.1.5] - 2026-10-21

### 달라진 것

- Pi가 Devin 로그인 세션을 요청마다가 아니라 하루에 한 번 다시 확인합니다. 그래서 Devin 요청과 모델 목록 갱신이 더 이상 매번 Pi의 공유 `auth.json` 잠금을 잡고 파일을 다시 쓰지 않습니다. 이전 버전에서 저장한 세션도 그대로 쓸 수 있으며, 다음에 사용할 때 확인합니다.
- 같은 Devin 계정으로 다시 로그인하면 모델 목록을 다시 받을 때까지 기다리지 않고 바로 보여 줍니다. 다른 계정에는 이전 계정의 모델을 보여 주지 않습니다.
- 패키지에 한국어 README(`README.ko.md`)를 함께 배포하고, README에 프로젝트 범위 설치를 확인하는 방법을 적었습니다.

### 해결된 것

- 같은 Pi agent 디렉터리를 쓰는 서브에이전트와 Fusion 보조 모델이 쓴 Devin 사용량 한도가 상태 표시줄과 `/devin`에 반영됩니다. 이전에는 현재 Pi 세션이 직접 Devin 요청을 보낼 때만 바뀌어서, Devin을 서브에이전트에서만 쓰면 값이 그대로였습니다.
- 상태 표시줄의 토큰 합계에 방금 끝난 응답이 포함됩니다. 이전에는 도구 호출이 이어지는 실행 중에 응답 하나씩 늦게 표시됐습니다.
- 상태 표시줄의 사용량 한도가 다음 응답을 기다리지 않고 로그인, 로그아웃, 계정 확인 직후에 갱신됩니다.

## [0.1.4] - 2026-10-21

### 해결된 것

- 사이드킥 연결이 끊겨도 리드 Pi가 종료되지 않고 해당 작업만 실패하도록 고쳤습니다. 전달 전에 취소된 호출은 백그라운드 호출을 포함해 사이드킥 작업을 시작하지 않습니다.
- 실행 중인 백그라운드 사이드킥 작업을 기다릴 때 같은 보고서가 두 번 전달되던 문제를 고쳤습니다. 긴 세션에서도 완료된 백그라운드 작업의 전달 기록이 계속 쌓이지 않습니다.
- 모든 전달 경로에서 오류 사유와 안내문까지 사이드킥 보고서 크기 제한에 포함합니다. 보존 파일에도 전달 보고서와 같은 상태·오류·본문 전체를 저장합니다.
- 요청 직전의 로그인 확인만 Devin 서버에 닿지 못했을 때 "OAuth refresh failed for devin: connect ECONNREFUSED"로 요청이 실패하던 문제를 고쳤습니다. 저장된 세션으로 요청을 보내며, 실제 장애라면 연결 오류 자체를 표시합니다.
- 모델 요청의 연결이 거부·초기화되거나, 시간이 초과되거나, 응답 도중 끊긴 경우와 Devin `unavailable`·HTTP 502~504 오류를 Pi가 자동으로 재시도합니다.
- Devin을 쓰는 Pi 세션이 여러 개일 때 요청마다 서로를 기다리지 않습니다. 요청이 15~40초 걸리거나 가끔 "Credential store read failed for devin: Lock file is already being held"로 실패하던 문제입니다.

## [0.1.3] - 2026-10-20

### 해결된 것

- `image_gen`처럼 매개변수 스키마가 `null`을 허용하는 도구가 있으면 `gemini-4-argon` 같은 Gemini 모델이 "There is an issue with this request, please try a different model" 오류로 실패하던 문제를 고쳤습니다. 이런 도구도 그대로 쓸 수 있으며, Devin 자체 도구처럼 매개변수마다 타입 하나로 선언됩니다.
- Claude·Gemini·GPT 모델의 정상 응답이 "stopReason cannot be treated as success" 또는 "Tool calls and the stop reason do not match" 오류로 실패하던 문제를 고쳤습니다. 이제 이 모델들의 도구 호출이 Pi에서 실행되고 최종 답변도 그대로 남습니다.
