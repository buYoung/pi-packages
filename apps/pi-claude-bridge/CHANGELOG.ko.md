## 0.14.0 — 2026-10-29

### 새로워진 것

- 다른 확장이 `src/index.ts`의 `createClaudeBridgeExtension({ getChildEnv })`로 브리지 인스턴스를 따로 만들어 기본 내보내기 대신 등록할 수 있습니다. 브리지는 모델 요청이나 요약을 처리할 Claude Code 프로세스를 시작하기 직전마다 `getChildEnv({ purpose })`를 부르고, 돌려받은 변수를 그 프로세스에만 더합니다. 이 변수는 브리지가 정하는 변수보다 우선하며, Pi의 환경, 로그, 오류 메시지에는 쓰이지 않습니다. `getChildEnv`가 예외를 던지거나 문자열 값만 담은 일반 객체가 아닌 것을 돌려주면 Claude Code를 시작하지 않고 요청을 실패로 끝냅니다. 기본 내보내기는 이전과 같이 동작합니다.

## 0.13.2 — 2026-10-28

### 달라진 것

- 브리지가 Claude Code 2.1.311(Agent SDK `^0.3.311`)을 사용합니다.
- 브리지가 Pi MCP 도구마다 서버가 선언한 `_meta`를 바꾸지 않고 Claude Code에 전달합니다. 서버가 `anthropic/maxResultSizeChars`를 선언하면 브리지의 기본값 52,224 대신 서버의 값을 씁니다. 브리지는 이 `_meta`를 `pi.getAllTools()`의 `meta`와, `pi.events`의 `tool-meta` 요청에 답하는 확장(예: `@buyong/pi-mcp-adapter`)에서 읽습니다. 1.4.0처럼 `pi.getAllTools()`에 `meta`가 없는 Pi 버전에서는 그런 확장이 있어야 합니다.

### 해결된 것

- Pi 도구 결과를 52,224자까지 Claude에 그대로 전달합니다. Pi 도구의 출력 한도(50KB)에 Pi가 출력을 자를 때 붙이는 안내 줄의 여유분을 더한 값입니다. 이전에는 브리지가 도구에 `anthropic/maxResultSizeChars`를 선언하지 않아서, Claude Code가 50,000자를 넘는 결과는 파일로 저장하고 Claude에 2KB 미리보기만 보여 주었고, 25,000토큰을 넘는 결과는 그 파일 경로를 담은 오류로 바꾸었습니다. 이 업데이트 전에 Claude Code가 이미 미리보기나 오류로 바꾼 결과는 그대로 남습니다.
- 응답 도중 연결이 끊겨 Claude Code가 요청을 다시 시도하면, 실패한 시도의 일부 텍스트가 다시 시도한 답변 앞에 남던 문제를 해결했습니다. 정상적으로 끝난 시도의 텍스트는 그대로 유지됩니다.
- `CLAUDE_BRIDGE_DEBUG=1`을 켠 상태에서 도구 호출을 여러 개 병렬로 실행할 때 브리지 로그에 잘못된 `BUG:` 경고가 기록되던 문제를 해결했습니다. 도구 결과는 이전에도 올바르게 전달되고 있었습니다.

## 0.13.0 — 2026-10-21

### 달라진 것

- 브리지가 Claude Code 2.1.304(Agent SDK `^0.3.304`)를 사용합니다.
- 디버깅이 꺼져 있으면 도구 결과를 디버그 미리보기용으로 직렬화하지 않습니다.
- 진단·CC CLI 로그 경로와 수동 정리 방법을 안내합니다. 로그를 자동으로 순환하거나 삭제하지는 않습니다.

### 해결된 것

- Pi 1.3.0에서 Haiku 5.5에 추론 끄기를 표시하지 않습니다. Claude Code가 이 모델의 추론을 유지하므로 끄기를 골라도 적용되지 않았습니다.
- 객체가 아닌 설정 파일은 시작을 막거나 원본을 덮어쓰지 않고 무시합니다.
- 진단 로그 쓰기 실패가 provider 요청을 중단하거나 원래 오류를 가리지 않도록 합니다.
- Claude Code가 비스트리밍 답변을 최종 결과에서 반복해도 본문을 한 번만 표시합니다.
- 격리 요약의 토큰 사용량을 반환하며, 이미 취소된 요청을 시작하지 않고 진행 중 취소도 다른 오류와 구분합니다.
- 종료 후 마지막 쿼리나 세션이 늦게 끝나더라도 공유 훅을 해제합니다.
- 수동 로그 정리 명령이 `~`로 시작하는 agent 디렉터리 설정도 홈 경로로 해석하도록 고칩니다.
- 시작 안내나 감지한 요금제를 기록할 때 전역 설정 파일을 한 번에 교체합니다. 동시에 시작한 Pi 프로세스나 하위 에이전트가 쓰는 도중의 파일을 읽고 사용자 설정 없이 실행되는 일이 없어집니다. 심볼릭 링크로 연결한 설정 파일은 링크로 유지합니다.
