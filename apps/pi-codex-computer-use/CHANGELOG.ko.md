## [0.3.2] - 2026-11-06

### 해결된 것

- 최신 Codex Desktop 빌드에서도 Computer Use가 네이티브 서비스에 다시 연결됩니다. 서비스는 Desktop이 서명한 프로세스가 포함된 체인에서만 연결을 받아들이므로, 브리지가 Desktop이 서명한 node 아래에서 런타임을 시작합니다. 이 수정이 없으면 앱 호출이 `Sky Computer Use native pipe startup failed`로 실패했습니다.
- Codex Desktop의 브라우저 접근 셸 래퍼 대신 그 안의 런타임 실행 파일을 실행합니다.

## [0.3.1] - 2026-11-02

### 새로워진 것

- Pi 1.5.0 이상에서는 이 패키지를 업데이트한 뒤 무엇이 바뀌었는지 보여 줍니다.

### 달라진 것

- 이제 Pi가 불러오는 파일만 담아 패키지 크기가 약 절반으로 줄었습니다. 타입 정의와 소스맵은 더 이상 넣지 않습니다. 문서도 패키지에서 빠지며, GitHub에서 계속 볼 수 있습니다.

## [0.3.0] - 2026-10-29

### 새로워진 것

- Computer Use가 켜져 있으면 `/computer-use-check`가 임시 런타임으로 네이티브 서비스에 접속해 앱 목록을 한 번 조회합니다. 보고서에서 Computer Use가 실제로 응답하는지 확인할 수 있습니다. 앱은 조작하지 않고 세션의 서버도 건드리지 않습니다.

### 해결된 것

- Browser Use 작업이 `The browser access host is unavailable`로 더는 실패하지 않습니다. 런타임 승인 대화상자는 그대로 동작합니다.

## [0.2.1] - 2026-10-21

### 달라진 것

- README에는 설치 경로와 승인·취소·출력 한도 요약을 남기고, 브라우저 작업의 시작 조건과 예상 결과를 포함한 세부 규칙은 사용법 문서에 모았습니다.

## [0.2.0] - 2026-10-21

### 달라진 것

- 이미지 데이터를 직렬화하지 않고 크기만 로그에 기록합니다.
- 첫 연결 뒤에는 저장한 도구 목록을 써서 세션 시작이 아니라 처음 도구를 호출할 때 `cua_repl` 서버를 시작합니다. Computer Use를 쓰지 않는 세션과 하위 에이전트가 서버를 띄워 두지 않고, 세션 시작도 서버를 기다리지 않습니다.

### 해결된 것

- 크기 제한을 넘는 MCP 응답이 오면 취소를 무한히 기다리지 않고 실행 중인 호출을 오류로 끝내며, 연결은 계속 쓸 수 있습니다.
- 큰 런타임 오류에도 일반 결과와 같은 출력 제한과 전체 출력 파일 저장을 적용합니다.
- 예기치 않은 서버 종료를 하단 상태에 반영하고, print·JSON 모드에서도 런타임 시작·종료 실패를 표시합니다.
- 종료 정리가 끝난 뒤 턴 알림 대기 타이머가 남지 않도록 수정했습니다.

## [0.1.3] - 2026-10-20
