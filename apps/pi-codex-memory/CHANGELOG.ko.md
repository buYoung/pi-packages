# 변경 이력

## [Unreleased]

### 새로워진 것

- 저장소 사본에서 `pnpm --filter @buyong/pi-codex-memory create-memory <세션 파일>`로 세션 파일 하나를 그 기억 범위의 설정과 모델로 기억으로 만듭니다. 그 범위의 기억이 꺼져 있어도 실행됩니다.
- `/codex-memory-settings`의 **Stop a model call after**로 기억 요청이나 요약 요청 하나가 실행될 수 있는 시간을 2분, 5분, 10분 중에서 정합니다.

### 달라진 것

- **호환성이 깨지는 변경:** 이 버전이 기억 DB를 처음 열 때 DB 버전을 2로 올리며, 그 뒤로는 이전 버전이 이 DB를 열지 못합니다. 이전 버전은 세션을 구간으로 나누지 않고 요약 요청 한 번에 들어가는 기억만 남기므로, 이전 버전으로 도는 Pi 세션이 이 버전이 만든 요약을 덮어쓰게 됩니다. 이미 열려 있던 세션은 처음 불러온 버전으로 계속 동작하므로, 업데이트한 뒤 열린 Pi 세션을 모두 다시 시작하거나 각 세션에서 `/reload`를 실행하세요. 이전 버전으로 되돌리려면 새 기억 DB가 필요합니다.
- 기억 생성 프롬프트에 길이 제한이 바이트 기준이고 한국어·중국어·일본어는 한 글자가 3바이트라는 점을 적었습니다. 그래서 이런 언어로 된 기억이 9,000바이트를 넘어 가운데가 잘릴 가능성이 줄어듭니다. 요약 프롬프트에도 10,000바이트 제한에 대해 같은 내용을 적었고, 요약 요청마다 지금 요약의 크기를 함께 보냅니다. 그래서 모델이 한도를 넘겨 덧붙이지 않고 오래된 항목을 줄이게 합니다.
- 모델 호출은 이제 기본적으로 2분이 아니라 10분 뒤에 멈춥니다. 그래서 느린 모델이나 높은 추론 강도로 만드는 요약도 끝날 수 있습니다. 전에 설정을 저장한 범위는 **Stop a model call after**를 바꾸기 전까지 2분을 씁니다.
- 모델 호출 한 번에 담기지 않는 긴 대화는 compaction 지점에서 구간으로 나누고, 구간마다 기억을 따로 만듭니다. 전에는 호출 한 번에 맞추려고 대화의 가운데를 잘라 내서 대부분이 빠졌고, 대화가 이어질 때마다 전체를 다시 처리했습니다. 이제 뒤의 compaction으로 닫힌 구간은 한 번만 처리하고, fork한 대화는 복사해 온 닫힌 구간을 다시 처리하지 않습니다.

### 해결된 것

- 이제 요약에 모든 기억이 반영됩니다. 전에는 기억이 모델 호출 한 번에 다 들어가지 않으면, 들어간 기억만으로 요약을 만들고 나머지는 끝내 요약에 넣지 않았습니다. 이제 최근 대화부터 여러 번에 나눠, 앞에서 만든 요약에 이어서 합칩니다.
- 대화에서 따로 언급한 폴더와 파일 이름을 합쳐 파일을 가리킨 기억을 더 이상 `ungrounded_identifier`로 거부하지 않습니다. `cd`로 폴더에 들어간 뒤 파일 이름만 쓴 경우가 그렇습니다. 대화에 나오지 않은 폴더 아래 경로는 지금처럼 거부합니다. 중괄호나 와일드카드로 여러 경로를 묶어 쓴 경로도 거부되므로, 기억 생성 프롬프트에 경로를 하나씩 그대로 쓰라고 적었습니다.
- 스크린샷이 많은 긴 대화처럼 16 MiB를 넘는 세션 파일도 기억이 됩니다. 전에는 알림 없이 건너뛰었습니다. 이제 세션 파일을 한 줄씩 읽으면서 이미지를 버리고, 더 처리할 것이 없는 파일은 바뀌기 전까지 다시 읽지 않습니다.
- 저장소에서 대화가 시작된 뒤에야 기억이 처음 본 대화나 그 대화를 fork한 대화도, 다음 세션 시작부터는 기억이 됩니다. **Create memories now**는 그 전의 내용도 포함하고 폴더가 지금 속한 저장소의 기억으로 만듭니다. 전에는 이런 대화가 기억이 되지 않았습니다.

## [0.2.0] - 2026-11-10

### 새로워진 것

- `/codex-memory`의 **Memory model**과 **Summary model**에서 모델을 고른 뒤 추론 강도를 고릅니다. **Default**나 그 모델이 제공하는 강도 중 하나를 고를 수 있고, 각 행에는 실제로 쓰는 강도가 `· high`처럼 함께 나옵니다.

### 달라진 것

- 이제 **Use current Pi model**은 Pi 세션의 추론 강도도 따르며, 모델이 그 강도를 제공하지 않으면 가장 가까운 강도를 씁니다. 이전에는 항상 기억 생성에 `low`, 요약에 `medium`을 썼습니다. 세션에서 추론을 끄면 기억도 추론 없이 만듭니다.
- 추론 강도만 바꿀 때는 대화 전송 동의를 다시 묻지 않습니다. 모델을 바꾸면 지금처럼 묻습니다.
- 이제 요청과 함께 전달된 요약에 나온 `thread_id`를 답에서 인용하면 그 기억을 사용한 것으로 칩니다. 요약으로만 쓰인 기억도 쓰지 않은 기억으로 지워지지 않으며, 이 인용도 상태 표시줄의 `cited`에 셉니다.

### 해결된 것

- 이미 쓰는 모델을 다시 골라도 설정한 추론 강도가 지워지지 않고, 강도를 설정한 모델이어도 모델 목록을 열면 그 모델에 커서가 놓입니다.
- **Delete unused memories after**로 지우는 기억이 더 이상 요약을 비우지 않습니다. 다음 요약 갱신에서 그 기억만 뒷받침하던 내용을 빼고, 갱신이 성공한 뒤 기억을 지웁니다.

## [0.1.0] - 2026-10-28

### 새로워진 것

- Pi 대화에서 결정과 맥락을 기억으로 추출·통합하고, 다음 세션에서 출처를 인용해 꺼내 씁니다. 켜기, 모델·범위, 저장된 기억은 `/codex-memory`, 시간·한도는 `/codex-memory-settings`에서 다룹니다.
- 기억은 꺼진 상태로 시작하며, 켤 때 마스킹한 대화 사본의 전송을 허용해야 합니다. 기억 생성과 요약은 각각 현재 Pi 모델이나 `/scoped-models`에서 고른 모델을 씁니다.
- 닫은 대화를 백그라운드에서 기억으로 만듭니다. 범위마다 열려 있는 Pi 세션 하나가 한 번에 최대 8개 대화를 처리하고, 그 세션이 닫히면 열려 있는 다른 세션이 이어받습니다. 기본값으로는 마지막 메시지 뒤 2시간이 지난 대화가 기억이 되고, 요약은 최대 2시간에 한 번 갱신하며, 최근 7일 안의 대화를 씁니다. `/codex-memory`의 **Create memories now**로 기다리지 않고 바로 실행할 수 있고, 진행 중인 작업은 같은 범위의 모든 세션 상태 표시줄에 나타납니다.
- 모델 호출 없이 기억을 고치거나 잊을 수 있고, 잊은 대화에서는 기억을 다시 만들지 않습니다. 에이전트에게 기억해 달라고 요청하면 확인을 받은 뒤 그 내용을 저장합니다.
- 같은 Git 저장소의 하위 폴더와 worktree가 기억을 공유합니다. 다른 저장소의 기억은 요청마다 확인하거나 한 방향 접근을 저장해 읽습니다.
- 대화를 압축해도 원래 사용자 발언을 추출 입력으로 씁니다.
- `@buyong/pi-codex` 번들에 포함됩니다.
