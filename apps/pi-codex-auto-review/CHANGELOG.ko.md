## [Unreleased]

## [0.8.1] - 2026-11-02

### 새로워진 것

- Pi 1.5.0 이상에서는 이 패키지를 업데이트한 뒤 무엇이 바뀌었는지 보여 줍니다.

### 달라진 것

- 이제 Pi가 불러오는 파일만 담아 패키지 크기가 약 절반으로 줄었습니다. 타입 정의와 소스맵은 더 이상 넣지 않습니다. 문서도 패키지에서 빠지며, GitHub에서 계속 볼 수 있습니다.

## [0.8.0] - 2026-10-29

### 달라진 것

- MCP 검토는 `tool-meta` 이벤트 채널에 답하는 확장(예: pi-mcp-adapter)에서 각 도구의 `_meta`(`codex_strict_auto_review`, `codex_sensitive_action`, `codex_requires_user_input`, 커넥터·계정 필드)를 읽습니다. Pi 내장 MCP 지원은 `_meta`를 넘기지 않으므로, 이를 쓸 때는 이 표시가 설정되지 않습니다.
- 보호 CLI와 `createGuardedRuntime()`은 `mcp` 옵션으로 설정한 Pi MCP 확장을 직접 로드합니다. `createGuardExtension()`은 이제 `mcp: false`만 받으며, 이 값을 주면 MCP 호출을 검토하지 않습니다. MCP 패키지 승인은 서버 설정·버전 대신 등록된 도구 정의를 기준으로 하므로, 이전 버전이 저장한 MCP 승인은 한 번 더 검토합니다.

### 해결된 것

- Auto Review가 더 이상 MCP 서버에 연결하거나 `/mcp`를 등록하지 않습니다. pi-mcp-adapter 같은 MCP 확장과 함께 설치하면 `/mcp`가 하나 더 보이고 모든 MCP 서버가 두 번 시작되던 문제를 해결했습니다. 이제 서버 연결은 Pi 내장 MCP 지원이나 이를 대체하는 확장이 맡고, Auto Review는 Pi가 MCP 도구를 실행하기 전에 `tool_call` 훅에서 호출을 검토합니다.

### 제거된 것

- 실행 중인 MCP 호출이 보내는 승인 요청(`elicitation/create`)에 대한 응답과, 보내는 `tools/call`마다 검토한 호출과 묶던 전송 단계 검사를 없앴습니다. 이제 Auto Review보다 나중에 로드한 확장의 `tool_call` 핸들러는 검토 뒤에 MCP 입력을 바꿀 수 있습니다.

## [0.7.0] - 2026-10-21

### 새로워진 것

- Pi의 Windows `powershell` 도구를 `bash`처럼 보호합니다. Codex에서 옮긴 리터럴 PowerShell 문법, cmdlet·별칭의 경로·네트워크 분류, 별칭의 문서상 이름까지 포함한 내부 명령 기준 규칙 대조, 읽기 검토 재사용, 셸을 밝힌 검토 증거를 제공합니다. 보호된 도구는 비활성 상태로 등록되므로 실행 여부는 계속 `defaultTools`나 `--tools`가 정하며, 보호 시작도 더는 이 도구를 제외하지 않습니다.

### 해결된 것

- MCP 취소·시간 초과 신호를 유지하고 실패하거나 취소한 요청의 추적 상태를 해제합니다.
- 일반 설치와 Off 모드에서도 Pi의 셸 탐색과 셸·이미지 설정을 유지합니다.
- Windows: `C:\tmp`를 기본 쓰기 루트로 보지 않습니다(`excludeSlashTmp`는 영향이 없습니다). Git Bash·MSYS2·Cygwin의 `/c/...` 같은 드라이브 경로를 대응해 보호 파일을 계속 거부하고, 다른 POSIX 절대 경로와 WSL 경로는 검토합니다. 파일 도구의 `/c/...`·`~\` 경로를 Pi와 같이 정규화하고, 규칙에서 `bash.exe` 래퍼와 Pi의 실제 셸을 인식하며, 역슬래시 구분자의 `.git` 메타데이터와 CRLF `gitdir` 포인터를 인식하며, 다른 호스트의 공유 경로는 승인 전에 해석하지 않고, 긴 Windows 환경이 한도를 넘어도 셸 호출 증거를 구조화된 형태로 유지합니다. 위치를 알 수 없는 셸 대상이 있으면 이전에 승인한 skill 패키지도 다시 검토하고, 신뢰한 `allow` 규칙도 그 명령을 승인하지 않습니다.
- macOS와 Windows의 대소문자·유니코드 정규화 차이, 그리고 Windows의 대체 데이터 스트림·장치 이름공간·예약 장치 이름·드라이브 상대 경로·로컬 관리 공유·끝의 점이나 공백·없는 구성 요소의 짧은 이름으로 보호 경로를 우회할 수 없습니다. 이런 경로는 거부하거나 `INVALID_PATH`로 실패하며, 허용 루트는 계속 정확히 비교합니다.
- 여러 단어로 된 `.env` 값을 포함해 크기가 제한된 조사 파일 원문을 발췌 전에 가립니다.
- 도움말·패키지 로딩 중 검토 DB를 만들지 않고 메모리 감사 기록을 제한합니다. 시작 실패와 감사 파일의 수동 정리 안내를 바로잡았습니다.
- 연결 끊김·과부하·요청 한도로 검토 요청이 실패하면 첫 실패에서 바로 거부하지 않고, 검토 기한 안에서 최대 두 번 다시 보냅니다.
- 실행 중인 다른 Pi 세션이 저장한 영구 규칙·패키지 승인·`/approve` 설정을 덮어쓰지 않고, 검토 캐시가 사용 중이면 100ms 뒤 바로 캐시 미스로 처리하는 대신 최대 1초 기다립니다.

## [0.6.0] - 2026-10-20

### 달라진 것

- 보호 CLI와 SDK가 Pi 1.0.0 이상에서 시작합니다. 1.0.0·1.1.0이 아닌 Pi 버전도 더는 `UNSUPPORTED_PI`로 실패하지 않으며, 1.0.0 미만은 계속 거부합니다.
- 소스 코드, 이슈, 릴리스 노트를 [pi-packages](https://github.com/buYoung/pi-packages) 저장소로 옮겼습니다.

### 제거된 것

- npm 압축 파일에서 `docs/publishing.md`와 `docs/publishing.ko.md`를 뺐습니다. 릴리스는 pi-packages 저장소의 절차를 따릅니다.
