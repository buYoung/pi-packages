- Effect 런타임 의존성을 4.1.2로 업데이트했습니다.

## [0.15.4] - 2026-11-02

- 타입만 선언하거나 개발용 CLI에서만 쓰는 모듈과 한국어 변경 기록을 더 이상 패키지에 넣지 않습니다.

## [0.15.3] - 2026-10-29

### 달라진 것

- Effect 런타임 의존성을 4.0.7로 업데이트했습니다.

## [0.15.2] - 2026-10-28

### 달라진 것

- 비동기 요청, 계정 선택, 캐시 공유, 카탈로그 갱신, 사용량 표시와 CLI 자원 정리를 Effect 4.0.6으로 리팩토링합니다. 공개 Promise API, 요청 정책과 저장 형식은 유지합니다.
- 변경 전후 설치본의 오프라인 계약 비교와 요청 예산을 제한한 실제 모델 50회 검증기를 추가합니다. 예산·취소 모의 테스트를 포함하며 기존 CI 배포 검증 조건은 바꾸지 않습니다.

## [0.15.1] - 2026-10-21

### 달라진 것

- README를 영문으로 바꾸고 한국어판을 `README.ko.md`로 함께 배포합니다. 설치 명령 앞에서 설치 경로를 고르게 하고, `!command` 키 참조를 다시 읽는 시점을 바로잡았습니다.

## [0.15.0] - 2026-10-21

### 달라진 것

- 계정이 동시 요청 한도(`429 "too many concurrent requests"`)에 걸리면 자리가 날 때까지 기다립니다. 여러 세션이나 하위 에이전트가 한 계정을 함께 쓰면 몰려서 생기는 오류입니다. 약 1·2·4·8·16초 뒤 같은 계정으로 다시 보내고, 그 뒤에는 Pi의 재시도가 이어받습니다.
- 세션을 연 채 Pi를 업그레이드해 Ollama Cloud 요청에 필요한 파일이 사라졌을 때 "Cannot find module"만 보여 주지 않고 Pi를 다시 시작하라고 안내합니다.

### 해결된 것

- 계정 상태의 잠금·저장 실패 뒤 미반영 변경을 보존하고, 다른 프로세스가 파일을 바꾸지 않았다면 다음 갱신 때 함께 저장합니다.
- print·JSON 모드에서 `/ollama` 결과·설정 저장 안내·오류를 stderr에 표시하며 JSON stdout은 유지합니다.
- 잔액 검사에서 키가 거부되면 참조를 다시 확인해 환경 변수의 새 값을 reload 없이 반영합니다. 명령 참조는 여전히 Pi 재시작이 필요합니다.
